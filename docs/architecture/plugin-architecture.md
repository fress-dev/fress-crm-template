# プラグイン設計方針

> **最終更新:** 2026-06-07  
> 現時点で**実装する範囲**と、将来の拡張の置き場所を定義する。  
> コア非変更の原則は [AGENTS.md](../../AGENTS.md) に従う。

## 層の名称

| 英語 | 日本語 | 旧称（参考） |
|------|--------|-------------|
| **Core** | コア | Platform |
| **Plugin** | プラグイン | 機能プラグイン・連携プラグイン |
| **Tenant Config** | テナント設定 | 顧客設定 |
| **Custom Layer** | カスタム層 | 顧客拡張 |

```
Core（常時）
  + Plugin（0〜複数）
  + Tenant Config（必須）
  + Custom Layer（必要なときだけ）
```

## 基本方針

- **業界パック（不動産一式・美容一式）は作らない。**
- **コアを土台に、必要なプラグインだけ載せる。**
- 店舗差は **テナント設定**（`tenants/<顧客>.json`）で吸収する。コードにしない。

## 今すぐ必要なもの

| 層 | 今やること | 置き場所（目安） |
|----|-----------|------------------|
| **コア** | プラグインレジストリ、`App.tsx` からの組み立て、カスタム層用の契約（型） | `src/platform/**`（移行中は `src/custom/`） |
| **テナント設定** | 有効プラグイン一覧、フォーム追加項目、商談段階、カスタム層参照 | `tenants/<顧客>.json`（最初は JSON のみでよい） |
| **プラグイン** | 最初の1本は要件が出たとき（例: 予約） | `src/plugins/<機能名>/**` |

## 今は不要（設計だけ頭に置く）

| 対象 | 理由 |
|------|------|
| **連携系プラグイン** | 顧客が外部連携を要するまで。最初はカスタム層 or 汎用 Webhook で足りる |
| **テナント設定のひな形** | 新規顧客用のコピー元 JSON。顧客が増えてからでよい |
| **業界パック** | 採用しない |

## 各層の定義

### コア（常時・1つ）

- atomic-crm の CRM（担当者・商談・メモ・タスク等）は触らない
- プラグイン登録 API・テナント設定の読み込み・日本語/JST
- **業務画面・業界固有ドメインは入れない**

### プラグイン（0〜複数）

- コアに後から足す**コードの単位**。業務・連携ともにプラグインと呼ぶ
- **1機能＝1プラグイン**。業界名は付けない（`appointments`、`properties` など）
- 申し込みの**型・フロー・画面**が別物のときだけ別プラグインにする
- フォームは固定せず、テナント設定から追加項目をマージできる拡張ポイントを持つ
- 連携（Webhook・外部 API）は将来、同じくプラグインとして追加する

### テナント設定（必須）

- その顧客の本番設定
- 入れるもの: 有効プラグイン、追加項目、表示/非表示、商談段階、連携 URL・鍵（将来）
- **ビジネスロジックは書かない**
- 新規導入時は任意のひな形 JSON をコピーして作成してよい

### カスタム層（必要なとき）

- テナント設定では足りない独自処理
- プラグインが定義する **Extension インターフェースを実装**して差し込む
- プラグイン本体の継承・複製はしない
- 例: `extensions/tenant-b/appointments.ts` をテナント設定から参照

## 差分の置き場所

| 違い | 対応 |
|------|------|
| 項目の有無・ラベル | テナント設定 |
| 申し込みの型・フローが違う | 別のプラグイン |
| 外部連携（将来） | 連携プラグイン → 当面はカスタム層 |
| 独自ロジック | カスタム層 |
| 本体ごと別物 | 例外（有償カスタム） |

## 導入例

| 顧客 | 構成 |
|------|------|
| 代理仲介（物件なし） | コア + テナント設定のみ |
| 物件管理＋内見 | コア + `properties` + `appointments` + テナント設定 |
| 依頼型申し込み | コア + `service-requests` + テナント設定 |

## 実装順序

1. コア — レジストリ + テナント設定の型 + Extension 契約
2. テナント設定の読み込み（1社分の JSON でよい）
3. プラグイン1本（要件が確定してから）
4. カスタム層（最初の例外要件が出たとき）
5. 連携プラグイン・テナント設定のひな形（顧客・連携が増えてから）

| 層 | ブランチ |
|----|----------|
| コア | `feat/platform-*` |
| プラグイン | `feat/plugin-<機能名>-*`（優先） |
| プラグイン（業界専用ドメイン） | `feat/plugin-realestate-*` / `feat/plugin-beauty-*`（機能名で切れないときのみ） |
